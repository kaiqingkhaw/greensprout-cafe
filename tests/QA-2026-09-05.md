# Café QA — 5 September 2026

## Fixed during this review

- Reproduced a search/debounce race: opening a product immediately after typing could make Add to Cart throw because its list index became stale. The modal now retains the selected product independently and updates its navigation bounds.
- Cart quantity buttons are labelled, bounded to 1–20, and add confirmations report the amount actually added.
- Delivery phone/address validation now matches the server more closely and trims surrounding whitespace before continuing to payment.
- Reviews use the saved profile identity instead of asking for an ignored name; duplicate clicks are blocked while saving, and the published list is fetched from the server.
- Admin status controls disable while saving and restore their previous value on API/network failure.
- Missing product edits no longer report success; missing product deletions report that the item was not found.
- Product editing uses a category select, field limits, accessible labels and inline error feedback that preserves entries.
- Operations tables now have customer/order/review search and live result counts. Product search has explicit no-results feedback.
- Corrected checkout number/label alignment, admin header wrapping and product-form spacing on phones. Shared admin headers are loaded statically to avoid inconsistent late styling.
- Removed the obsolete contact-success block exposed to assistive technology. Updated the About footer year and misleading account favourites copy.
- Updated asset versions to prevent old cached scripts/styles from obscuring changes.

## Limits

This is a broad functional regression and sampled responsive review, not proof that every possible interaction is bug-free. No exhaustive cross-browser, load/concurrency, penetration or full screen-reader certification. Destructive admin paths and password changes were tested through HTTP against temporary fixtures, not by changing real accounts through the UI. Some external media, maps, fonts and charts depend on third-party availability.

Payments remain explicitly simulated. No real card data is accepted by the demo UI, stored or charged; real gateway integration is outside this pass. Contact messages are stored locally, not emailed. Customer photo removal unlinks the image but retains old upload files under the existing retention policy.
